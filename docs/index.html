Open source · for every coding agent

Every session picks up where the last one left off.

Agentbook keeps a handbook beside your code: what the project is, every decision and why, every question you asked and its answer. Your agent reads it first and keeps it current. On any computer, with any agent.

§ 01

Notes that live with the code, and an agent that actually keeps them.

Coding agents forget everything between sessions. Each project gets one private repo you clone and open. It holds your code in code/ and a handbook around it, plus rules in AGENTS.md that every agent reads first. Git hooks make sure the handbook keeps up.

private my-app what you clone

├── AGENTS.md          rules every agent reads first
├── STATUS.md          where things stand, next step
├── DECISIONS.md       every decision, why, what lost
├── history/sessions/  every question and answer
├── kit/               sync, check, find, hooks
└── code/              your code
go public

public my-app code only

├── src/ README LICENSE
└── only the code's own commits.
     no notes, ever.

The handbook stays private as my-app-handbook and fetches the public code into code/.

§ 02

The routine is four sentences.

  1. 1

    Open

    Open the project folder in your agent. On a new computer, clone your private repo first.

  2. 2

    Work

    Say what you want. Ask about the past: did we look into…?

  3. 3

    Save

    Say commit and push. The handbook travels with the code.

  4. 4

    Stop

    Say wrap up. Even talk-only sessions reach your next computer.

§ 03

A small command for the moments that are yours.

Your agent runs the kit for you. agentbook covers the human parts: starting a project, seeing where it stands, searching the past, and checking it's all saved before you close the laptop.


      

    

    
Keyboard first, instant start, readable on light and dark terminals.

  


  

    
§ 04

    
What happens on its own.

    

      
Sessions start in sync
The agent's first step fetches the code and handbook, installs what it can and connects the hooks. Even on a brand-new computer.

      
Every commit is logged
Each code commit lands in the handbook's commit log, so what changed and why sit side by side.

      
Stale notes stop the push
No session log today, a handbook older than the code, or failing tests: the push is blocked, with the reason.

      
Code and notes never mix
In a one-repo project a commit can't touch both, so the code's history can go public cleanly at any time.

      
The past has answers
Questions like "did we already…?" are answered from the records, with file and date. If it was never discussed, it says so.

      
Nothing private leaks
Agent rule files inside code/ are local links, hidden from git. An optional guard keeps AI traces out of pushed code.

    

  


  

    
§ 05

    
Say it, and it's done.

    
Each scenario starts with something you say to your agent.

    

      
Start a brand-new project
        
Run agentbook init in an empty folder, or say:
Set up an agentbook for this project using github.com/EnigmaticZee/agentbook; follow its PROMPT.md.
You get one repo with the handbook and an empty code/ folder. Nothing goes online until you decide.

      
Add it to a project you already have
        
Same thing, inside the project. It tells you before moving anything: the folder keeps its path, your code moves into code/ with its full history and local files, and the agent writes the handbook from the code and its history.

      
Put it on GitHub, privately
        
Put this project on private GitHub.
One private repo with the handbook and the code. It can stay like this forever.

      
Make it public
        
Get this ready to go public.
It shows exactly what would be published (only the code's own commits), audits it for secrets, personal paths and private files, and goes through each finding with you. Only after your yes does the code get its own public repo. Your notes stay private and keep working.

      
Continue on a new computer
        
Clone your private repo and open it in your agent. It fetches anything missing, installs what it can and connects everything before it starts.

      
Ask about something from before
        
Did we look into SQLite? Why did we drop the plugin idea?
The agent searches the handbook and every session log and answers with where it came from. Or search yourself with agentbook find.

      
Someone else contributes
        
Public projects: nothing to do. Contributors clone only the public code; your handbook and hooks don't exist for them.

      
A push is blocked
        
Usually nothing to do: the agent updates the handbook or fixes the tests and pushes again. To push anyway, say push without the checks this time.

    

  


  

    
§ 06

    
Install.

    

      

        
        
        
        
      

      
Set up an agentbook for this project using github.com/EnigmaticZee/agentbook; follow its PROMPT.md.
Paste it into any coding agent, in a new or existing project folder. Nothing else to install.

      
go install github.com/EnigmaticZee/agentbook/cmd/agentbook@latest
Installs the agentbook command from source. Then run agentbook init.

      
brew install enigmaticzee/tap/agentbook
macOS and Linux. Available from the first release.

      
curl -fsSL https://enigmaticzee.github.io/agentbook/install | sh
Downloads the latest release and checks its checksum (read the script). Available from the first release.

    

    
Needs git and bash. Works with Claude Code, Codex, Cursor, GitHub Copilot, Gemini CLI, Amp, Jules, Zed and anything else that reads AGENTS.md.
